# پورتفولیو ساز — Portfoilo Builder

استودیوی فارسی و راست‌چین برای ساخت پورتفولیو، الهام‌گرفته از رابط بنفش و آبی مرجع پروژه.

## امکانات نسخه ۱

- ویزارد چهارمرحله‌ای: مشخصات و مهارت‌ها، پروژه‌ها، قالب و پالت، دامنه و خروجی.
- شش قالب مرجع کدکرفت، اورگرین، کورال، آمتیست، لرن‌هاوس و ادوویولت؛ ۳۲ رنگ آماده و انتخاب رنگ دلخواه برای اجزای قالب.
- پیش‌نمایش زنده، نمای موبایل و بزرگ‌نمایی.
- تصویر پروفایل و تصاویر پروژه با کوچک‌سازی محلی؛ حداکثر ۱۲ پروژه.
- پیش‌نویس محلی خودکار، خروجی و بازیابی JSON، اطلاعات نمونه با تأیید جایگزینی.
- خروجی HTML کامل و مستقل با تصاویر داخلی، متادیتا و طراحی واکنش‌گرا.
- ورود GitHub OAuth و ذخیره JSON هر کاربر در مخزن خصوصی جداگانه؛ کنترل مالکیت بر اساس شناسه تأییدشده گیت‌هاب.
- کنترل تداخل نسخه برای جلوگیری از بازنویسی ناخواسته داده، محدودیت حجم و نرخ درخواست، کوکی HttpOnly، SameSite و کنترل Origin.

## اجرای سریع

نیازمندی: Node.js 22 یا بالاتر. برنامه وابستگی npm ندارد.

```sh
npm start
```

سایت در `http://localhost:3000` اجرا می‌شود. بدون متغیرهای محیطی، ویزارد، تصاویر، پیش‌نمایش، پشتیبان و خروجی مستقل کار می‌کنند؛ دکمه ورود حالت محلی را نشان می‌دهد.

```sh
npm run check
npm test
```

## فعال‌کردن ورود و ذخیره آنلاین

کد برنامه می‌تواند عمومی باشد؛ **داده کاربران نباید در همین مخزن عمومی قرار بگیرد**. سرور عمداً نوشتن و خواندن داده از مخزن عمومی را رد می‌کند.

1. یک مخزن **Private** مخصوص داده بسازید. یک README اولیه اضافه کنید.
2. یک GitHub OAuth App بسازید. Homepage برابر دامنه برنامه و Callback برابر `https://YOUR-BUILDER-DOMAIN/auth/callback` باشد.
3. `.env.example` را به `.env` کپی و متغیرها را تکمیل کنید. در هاست از بخش Secrets/Environment استفاده کنید.
4. `GITHUB_DATA_TOKEN` یک fine-grained token فقط برای همان مخزن داده با Contents read/write و Metadata read باشد. `GITHUB_CLIENT_SECRET` و توکن هرگز در مرورگر یا git قرار نمی‌گیرند.
5. `SESSION_SECRET` دست‌کم ۳۲ نویسه تصادفی باشد. `APP_ORIGIN` باید دقیقاً origin سایت، بدون اسلش انتهایی، باشد.
6. پس از راه‌اندازی دوباره سرور، ورود گیت‌هاب و دکمه ذخیره مرحله آخر فعال هستند.

ساختار داده: `portfolios/<verified-github-user-id>/profile.json`. اطلاعات و تصاویر کوچک‌شده داخل همین JSON هستند. هیچ شناسه کاربری از ورودی مرورگر برای انتخاب مسیر پذیرفته نمی‌شود. در هر حساب یک پورتفولیو ذخیره می‌شود. ابتدا برای ویرایش رکورد موجود «بازیابی از حساب من» را بزنید. در برخورد نسخه‌ها ابتدا از پیش‌نویس پشتیبان بگیرید.

## دامنه و انتشار

نام دامنه در مرحله چهارم ثبت و اعتبارسنجی می‌شود، اما ثبت نام، خرید یا اتصال DNS خودکار نیست. خروجی HTML را با نام `index.html` در ریشه هاست یا یک static host قرار دهید؛ دامنه و HTTPS را مطابق پنل همان میزبان تنظیم کنید. برنامه سازنده به هاست Node.js یا Docker نیاز دارد؛ GitHub Pages برای بخش سرور و ذخیره آنلاین کافی نیست. رمز پنل دامنه از کاربر دریافت نمی‌شود.

```sh
docker build -t portfoilo-builder .
docker run --env-file .env -p 3000:3000 portfoilo-builder
```

## حدود فعلی

این نسخه پایه قابل اجراست. انتشار خودکار برای هر کاربر، خرید دامنه، اتصال DNS، بازیابی رمز و پرداخت در آن وجود ندارد. OAuth فقط گیت‌هاب است. نشست‌های ورود در حافظه فرایند نگهداری می‌شوند؛ با ری‌استارت ورود مجدد لازم است و برای چند replica باید session store مشترک اضافه شود. مخزن گیت‌هاب برای تعداد کم کاربران مناسب است؛ تعداد زیاد کاربران و تصاویر به ذخیره‌ساز و پایگاه‌داده اختصاصی نیاز دارد. حذف یا اصلاح داده در آخرین commit، تاریخچه git را پاک نمی‌کند. پیش‌نویس مرورگر دستگاه مشترک خصوصی محسوب نمی‌شود.

تست‌ها اعتبارسنجی، خروجی HTML، جلوگیری از تزریق، مسیرهای سرور و کنترل Origin را پوشش می‌دهند. اتصال زنده OAuth/مخزن داده و دامنه باید پس از تنظیم Secrets در محیط مقصد آزموده شود.

## طراحی نسخه ۳ — شش مرجع ارسالی

قالب‌های قبلی حذف شده‌اند. شناسه قدیمی در پیش‌نویس‌ها به کدکرفت تبدیل می‌شود؛ مشخصات و پروژه‌ها حفظ می‌شوند. صفحه اصلی مستقل در `/` و ویزارد در `/builder` است.

| شناسه | مرجع | ساختار |
| --- | --- | --- |
| codecraft | توسعه‌دهنده تیره | پرتره با هاله بنفش، کارت کد، شبکه مهارت‌ها، پروژه‌ها |
| evergreen | خانه در طبیعت | هیروی کاور، نوار شناور زیتونی، معرفی دو ستونی، کارت پروژه |
| coral | طراح هلویی | پرتره دایره‌ای، کارت شیشه‌ای ارتباط، نمونه‌کارهای سه ستونی |
| amethyst | متخصص یاسی | پرتره قدی، کارت آمار از داده واقعی، خدمات آیکون‌دار، معرفی |
| learnhouse | مربی سبزآبی | هیروی سبزآبی، دکمه زرد، لبه منحنی، خدمات قاب‌دار، مسیر حرفه‌ای |
| eduviolet | آموزش بنفش‌صورتی | قاب خط‌چین، کارت‌های شناور، نوار مهارت، پروژه‌ها در گرادیان |

فونت واقعی **Vazirmatn** با وزن معمولی و ضخیم به صورت WOFF داخلی استفاده شده است. فایل خروجی هم فونت و مجوز OFL را همراه دارد. کاور، تیتر اصلی و فهرست خدمات در ویزارد قابل ورود هستند. رنگ پیش‌فرض هر قالب از مرجع گرفته شده؛ انتخاب دستی پالت آن را تغییر می‌دهد. تغییر قالب رنگ بومی آن را برمی‌گرداند.

تصاویر مرجع برای چیدمان و سبک استفاده شدند؛ تصاویر اشخاص و شرکت‌ها، لوگوهای مشتریان، نظرات و آمار تبلیغاتی آن‌ها به نام کاربر درج نمی‌شوند. تصاویر واقعی پورتفولیو از بارگذاری‌های کاربر می‌آیند؛ جای خالی آن‌ها با طرح گرافیکی پر می‌شود. قالب آموزشی در این نسخه ارائه تخصص و پروژه است، نه سامانه فروش دوره.

بررسی‌های خودکار شامل شش قالب جدید، فونت داخلی، حفظ فیلدهای پشتیبان، ناوبری داخلی، اعتبارسنجی و مسیرهای سرور است. بررسی بصری مرورگر در این محیط تأیید نشده است.

## دموی تصویری نسخه ۳.۱

دو دکمه «دموی زن» و «دموی مرد» در صفحه ساخت قرار دارند. جایگزینی پیش‌نویس با تأیید انجام می‌شود و قالب و رنگ فعلی حفظ می‌شود. هر دمو تصویر پروفایل PNG شفاف، تصویر کاور، اطلاعات فارسی و سه پروژه با تصویر دارد. پیش‌نمایش گالری صفحه اصلی و انتخاب قالب هم از همین داده مشترک استفاده می‌کنند. همه تصاویر هنگام ورود به دمو به data URL تبدیل می‌شوند تا JSON پشتیبان و HTML خروجی مستقل باشند.

فایل‌های نهایی در `public/assets/demo/` قرار دارند: `man.png`، `woman.png`، `architecture.webp`، `dashboard.webp` و `branding.webp`. پرتره‌ها شفاف‌اند و دارایی‌ها برای وب کوچک شده‌اند. شخصیت‌ها، اطلاعات و پروژه‌ها نمایشی و تصاویر با ابزار تولید تصویر ساخته شده‌اند.

پرامپت‌ها: پرتره استودیویی مرد ایرانی با پیراهن زغالی روی زمینه شفاف؛ پرتره زن ایرانی با روسری کرم و کت یاسی روی زمینه شفاف؛ خانه چوب و شیشه در باغ جنگلی؛ ماکاپ لپ‌تاپ با داشبورد بنفش؛ عکاسی بسته‌بندی آرایشی هلویی. از حالت داخلی تولید تصویر استفاده شد.

## نسخه ۳.۲ — چیدمان فشرده و پیش‌نمایش منعطف

عرض محتوای سازنده تا ۱۲۰۰ پیکسل محدود شده، فاصله‌ها، هیرو، تیترها و کنترل‌ها کوچک‌تر شده‌اند. صفحه ساخت بالای عرض ۹۰۰ پیکسل دو ستون دارد و در عرض‌های پایین‌تر تک‌ستونه است. روی نمایشگرهای کوتاه، ارتفاع هیرو و پیش‌نمایش کاهش می‌یابد؛ کنترل‌های لمسی حداقل ارتفاع ۴۴ پیکسل دارند.

ماژول `public/preview.js` اندازه واقعی کادرها را با ResizeObserver می‌سنجد و پیش‌نمایش دسکتاپ، موبایل و کارت قالب‌ها را بدون برش افقی در کادر جا می‌دهد. فونت فرم و متن اصلی صفحه با scale کوچک نمی‌شود؛ فقط تصویر زنده داخل iframe مقیاس می‌گیرد. هر شش قالب خروجی نیز فاصله‌ها، تیترها و تصاویر فشرده‌تر و قواعد عرض میانی جداگانه دارند.

## نسخه ۳.۳ — آیکن و حرکت

- مجموعه SVG محلی برای کنترل‌های دسکتاپ/موبایل، بزرگ‌نمایی، خروجی، پشتیبان، دمو، حذف و خدمات قالب‌ها؛ بدون وابستگی خارجی.
- اسکرول اصلی صفحه ساخت، پیش‌نمایش را بر اساس پیشرفت نسبی ویزارد هدایت می‌کند. چرخ ماوس و لمس در پیش‌نمایش به همان اسکرول صفحه منتقل می‌شوند. در نمایش تک‌ستونه، موقعیت خود کادر پیش‌نمایش مبناست. بزرگ‌نمایی امکان مرور همان پیش‌نمایش را دارد.
- پیش‌نمایش اصلی فقط اجازه اجرای اسکریپت محدود ارتباطی دارد (`sandbox=allow-scripts`، بدون same-origin). پیام‌های ورودی در هر دو طرف با منبع پنجره بررسی می‌شوند. خروجی HTML سایت فاقد این اسکریپت است.
- حرکت آرام ویترین، نشان‌های شناور و آشکارشدن بخش‌ها هنگام ورود به صفحه. رد ماوس با Canvas و سقف ۹۰ ذره، فقط برای ماوس دقیق؛ بدون تغییر نشانگر اصلی یا گرفتن کلیک‌ها. با توقف حرکت، حلقه رسم پایان می‌یابد.
- تنظیم سیستم برای کاهش حرکت رعایت می‌شود و افکت اشاره‌گر در صفحات لمسی غیرفعال است.

تست ارتباط پیش‌نمایش، کنترل منبع پیام و انتقال چرخ ماوس و لمس انجام شده است. رفتار نهایی بصری/اسکرول در مرورگر واقعی این محیط تأیید نشده است.

## نسخه ۳.۴ — اصلاح نمایش و خروجی

- پیش‌نمایش تمام‌صفحه از عرض واقعی کادر استفاده می‌کند؛ نوارها ارتفاع ثابت دارند و سایت فضای باقی‌مانده را پر می‌کند. حالت موبایل عرض تلفن را حفظ می‌کند. خروج با دکمه بستن یا Escape امکان‌پذیر است.
- در تمام‌صفحه اسکرول، لمس و لینک‌های داخلی سایت طبیعی عمل می‌کنند؛ پس از بستن، ارتباط اسکرول ویزارد دوباره برقرار می‌شود.
- حاشیه و قاب بیرونی اورگرین حذف شده است. محدودیت عرض روی پس‌زمینه بخش‌های عریض برداشته شده و ستون‌های قالب‌ها در موبایل از محتوا بزرگ‌تر نمی‌شوند.
- حرکت ویترین با JavaScript و Web Animations اجرا می‌شود؛ نقطه‌های بنفش درخشان Canvas برای ماوس و قلم فعال‌اند و تنظیم کاهش حرکت سیستم رعایت می‌شود. اجرای افکت به بارگذاری گالری وابسته نیست.
- بررسی مرورگری هر شش قالب با داده‌های دمو در عرض ۱۳۳۷ و ۳۶۰ پیکسل: عرض سند برابر عرض نمایش بود. تمام‌صفحه و رد ذرات ماوس نیز بصری بررسی شدند. دانلود HTML از دکمه اصلی آزمایش شد؛ بازکردن فایل محلی دانلودشده در مرورگر محیط مجاز نبود. همان مولد HTML در خروجی و پیش‌نمایش استفاده می‌شود.
- تست‌های بازگشت برای اندازه تمام‌صفحه، اسکرول طبیعی و افکت‌های ماوس اضافه شدند.

## نسخه ۳.۴.۱ — عکس شخصی بدون برش

نمایش پرتره در هیرو، معرفی و قاب کوچک شخصی با `object-fit: contain` انجام می‌شود؛ تصاویر کاور و نمونه‌کار همچنان قاب خود را پر می‌کنند. قاب دایره‌ای کورال اکنون پس‌زمینه مستقل دارد و بدن سوژه را قطع نمی‌کند. نمایش عکس دموی زن در هر شش قالب در حالت دسکتاپ و موبایل در مرورگر بررسی شد. این CSS در خروجی HTML مستقل نیز استفاده می‌شود.

پیش‌نویس‌های مرورگر تصاویر را همراه خود ذخیره می‌کنند. عکس ناقص دموی قدیمی به‌صورت خودکار و بدون تغییر اطلاعات دیگر تعمیر می‌شود. اگر مرورگر قدیمی Web Crypto ندارد، پس از گرفتن پشتیبان، دموی جدید را انتخاب کنید. برای عکس شخصی، فایل اصلی باید نیم‌تنه داشته باشد.

علت اصلی پرتره‌های ناقص، قطع‌شدن فایل PNG زن در ۴۷۱۹۹ بایت و مرد در ۸۱۶۳۸ بایت هنگام ثبت نسخه‌های قبلی بود. هر دو فایل با نسخه کامل جایگزین شدند. در مرورگرهای دارای Web Crypto، پیش‌نویس‌های حاوی دقیقاً این دو فایل قدیمی با بررسی SHA-256 شناسایی می‌شوند و فقط عکس آن‌ها از فایل کامل بازیابی می‌شود؛ متن‌ها و پروژه‌های کاربر حفظ می‌شوند.

## نسخه ۳.۵ — خروجی وب‌سایت و قالب وردپرس

مرحله چهارم و نوار پیش‌نمایش دو خروجی مستقل دارند:

- **سایت HTML:** خروجی فعلی مستقل با فونت و تصاویر درون فایل، برای هاست استاتیک.
- **قالب وردپرس ZIP:** یک پوشه پوسته با `style.css`، `functions.php`، `header.php`، `footer.php`، `front-page.php`، `index.php`، `singular.php`، `404.php`، `comments.php`، `theme.json`، فونت و تصاویر محلی و داده‌های عمومی ویزارد. هر شش طرح قابل خروجی‌اند.

### نصب و مدیریت در وردپرس

1. وردپرس را روی هاست نصب کنید؛ ZIP خروجی را از **نمایش ← پوسته‌ها ← افزودن ← بارگذاری پوسته** نصب و فعال کنید.
2. مشخصات، خدمات، مهارت‌ها، عکس نیم‌تنه، کاور و رنگ تأکیدی در **نمایش ← سفارشی‌سازی ← اطلاعات پورتفولیو** قابل ویرایش‌اند. فهرست اصلی از فهرست‌های وردپرس قابل تنظیم است.
3. پروژه‌های واردشده در ویزارد بلافاصله نمایش داده می‌شوند. برای مدیریت پویا، در **نمایش ← راهنمای پورتفولیو** پروژه‌ها را با اقدام صریح مدیر به نوشته‌های **پیش‌نویس** همراه تصاویر رسانه وارد کنید؛ سپس بازبینی و منتشر کنید و دسته ساخته‌شده را در سفارشی‌سازی انتخاب کنید. اگر دسته پروژه انتخاب شود، فقط نوشته‌های منتشرشده آن دسته نمایش داده می‌شوند؛ انتخاب دسته خالی، پروژه‌ای نشان نمی‌دهد.
4. عنوان، چکیده یا متن، تصویر شاخص و صفحه پروژه با ابزارهای خود وردپرس ویرایش می‌شوند. واردسازی تکرارشونده رکورد تکراری ایجاد نمی‌کند. فعال‌کردن قالب نوشته یا تنظیمات صفحه اصلی وردپرس را تغییر نمی‌دهد.

این خروجی **قالب کلاسیک وردپرس** با پشتیبانی از محتوای بلوکی برگه‌ها و نوشته‌هاست. بخش‌های پورتفولیو با Customizer و داده‌های وردپرس تولید می‌شوند؛ از نسخه ۳.۶، صفحه اصلی، سربرگ و فوتر با ویجت‌های بومی المنتور رایگان نیز خروجی گرفته می‌شوند؛ ویرایش کامل پوسته در Site Editor ارائه نمی‌شود. طراحی انتخاب‌شده هنگام خروجی مشخص می‌شود. حداقل اعلام‌شده WordPress 6.0 و PHP 7.4 است؛ بررسی اجرایی روی WordPress 7.1.4 با PHP 8.4.27 و دیتابیس آزمایشی SQLite انجام شد.

خروجی‌ها فقط در مرورگر ساخته می‌شوند؛ ارسال اطلاعات به سرور یا حساب وردپرس برای ساخت ZIP لازم نیست. فایل ZIP شامل اطلاعات عمومی و تصاویری است که در ویزارد وارد شده‌اند. تصاویر به فایل‌های واقعی و فونت به WOFF محلی تبدیل می‌شوند. داده کاربر در JSON ذخیره و هنگام خروجی HTML با توابع escaping وردپرس نمایش داده می‌شود؛ داده واردشده به کد PHP تبدیل نمی‌شود. واردسازی با کنترل دسترسی مدیر و nonce محافظت می‌شود.

### اعتبارسنجی خروجی

- `npm run check` و `npm test`: ساختار شش پوسته، نبود نشانگرهای موقت، جداسازی داده از PHP، بررسی ZIP با decoder مستقل Python، حفظ باینری تصاویر/فونت و بررسی syntax همه PHPها.
- برای فعال‌شدن تست PHP، `php` در PATH باشد یا `PFB_PHP_BIN` مسیر اجرایی PHP را مشخص کند؛ در نبود PHP فقط همان تست با دلیل مشخص skip می‌شود.
- نصب هر شش ZIP با `Theme_Upgrader` خود وردپرس موفق بود. Customizer و کنترل رسانه، پاکسازی داده، escape متن، نمایش پروژه‌های ویزارد، نوشته و چکیده بومی و محتوای بلوکی آزموده شدند. بعد از تکمیل محیط آزمایش، رندر شش پوسته بدون خطای PHP در log انجام شد.
- واردسازی دوباره سه پروژه: سه پیش‌نویس و سه تصویر شاخص، بدون تکرار.
- دکمه‌های دریافت HTML و WordPress ZIP در مرورگر آزمایش شدند. سازگاری با همه افزونه‌ها و هاست‌ها بررسی نشده است.

مراجع ساختار: [Theme files](https://developer.wordpress.org/themes/releasing-your-theme/required-theme-files/)، [WordPress hooks](https://developer.wordpress.org/themes/advanced-topics/plugin-api-hooks/)، [Customizer](https://wordpress.org/documentation/article/customizer/).

## نسخه ۳.۶ — پوسته با صفحه‌ساز المنتور و پنل راه‌اندازی

خروجی «وردپرس + المنتور ZIP» برای هر شش طرح، صفحه اصلی، سربرگ و فوتر را به اسناد **بومی المنتور** تبدیل می‌کند. متن، عنوان، عکس، دکمه و هر کارت پروژه ویجت مستقل است؛ کانتینرها و تنظیمات رنگ، اندازه، فاصله و چیدمان موبایل در خود داده المنتور ذخیره می‌شوند. صفحه داخل iframe یا یک ویجت HTML بزرگ قرار نگرفته است.

### استفاده

1. ZIP جدید را در **نمایش ← پوسته‌ها ← افزودن ← بارگذاری** نصب و فعال کنید.
2. به **نمایش ← راه‌اندازی پورتفولیو** بروید. المنتور رایگان را از مخزن رسمی وردپرس نصب و فعال کنید؛ افزونه به‌صورت مخفی یا خودکار نصب نمی‌شود.
3. «ساخت صفحات قابل ویرایش» را بزنید. تصاویر به رسانه‌ها و صفحه اصلی، سربرگ و فوتر به اسناد المنتور منتقل می‌شوند. ابتدا اسناد پیش‌نویس‌اند. دو گزینه جداگانه برای انتشار و تعیین صفحه اصلی و فعال‌کردن سربرگ/فوتر وجود دارد؛ بدون انتخاب آن‌ها، صفحه اصلی فعلی و سربرگ سایت تغییر نمی‌کنند.
4. با دکمه **ویرایش با المنتور** کنار هر سند، متن‌ها، تصاویر، ستون‌ها، دکمه‌ها و کارت‌ها را ویرایش کنید. اجرای دوباره راه‌انداز شناسه اسناد را حفظ می‌کند و ویرایش‌های انجام‌شده را بازنویسی نمی‌کند.
5. از پنل قالب، JSON صفحه، سربرگ و فوتر را دریافت کنید. پس از ویرایش، داده فعلی همان سند صادر می‌شود. تصاویر JSON به رسانه/نشانی سایت اشاره می‌کنند؛ انتقال آن به سایت دیگر به دسترسی به آن تصاویر نیاز دارد. تصاویر اولیه همراه ZIP پوسته‌اند.

پنل گزینه‌های سربرگ ثابت و دکمه شناور بازگشت به بالا دارد. محل‌های Theme Builder پرو نیز ثبت شده‌اند؛ اگر طرح پرو برای یک محل فعال باشد، آن طرح اولویت دارد. مسیر اصلی صفحه، سربرگ و فوتر به نسخه Pro نیاز ندارد؛ Pro همراه بسته نیست و سازگاری اجرایی با آن در این مرحله آزمایش نشده است.

پس از ساخت صفحه المنتوری، منبع ویرایش آن **المنتور** است. اطلاعات Customizer، حالت کلاسیک را کنترل می‌کنند و محتوای ویرایش‌شده المنتور را تغییر نمی‌دهند. کارت‌های پروژه در المنتور و نوشته‌های وردپرس مستقل‌اند؛ می‌توانید کارت را به نوشته پروژه پیوند دهید. قالب همچنان برگه، نوشته، دیدگاه، جست‌وجو، آرشیو، منو، لوگو و حالت جایگزین کلاسیک را دارد. این نسخه مجموعه امکانات مخصوص پورتفولیو است؛ فروشگاه و امکانات تجاری وودمارت به آن اضافه نشده‌اند.

### بررسی انجام‌شده

- ذخیره و رندر ۱۸ سند (صفحه/سربرگ/فوتر در شش طرح) با WordPress 7.1.4، Elementor Free 4.3.6 و PHP 8.4.27 در محیط آزمایشی جداگانه.
- صفحه هر طرح ۴۳ تا ۵۷ ویجت بومی قابل ویرایش دارد. نوع ویجت‌ها در خود المنتور شناسایی و رندر شد؛ تصویرها به شناسه و URL واقعی رسانه تبدیل شدند.
- ذخیره یک تغییر با API اسناد المنتور و اجرای مجدد راه‌انداز: شناسه و ویرایش قبلی حفظ شد؛ ایجاد پیش‌نویس به‌تنهایی صفحه اصلی را عوض نکرد.
- خروجی کورال در مرورگر با ۶۲ ویجت صفحه/سربرگ/فوتر، پنج تصویر سالم و بدون بیرون‌زدگی افقی دیده شد. بررسی تصویری داخل محیط ویرایشگرِ نیازمند ورود انجام نشده است؛ ذخیره و ویرایش از API واقعی المنتور آزمایش شده است.
- تست‌های ساختار JSON، مستقل‌بودن ویجت‌ها، بسته‌بندی تصاویر و متن ایمن به تست‌های ZIP و PHP اضافه شدند. هشدارهای deprecation داخلی Elementor روی PHP 8.4 در لاگ دیده شد؛ خطای اجرایی در کد پوسته مشاهده نشد.

مراجع: [ساختار کانتینر المنتور](https://developers.elementor.com/docs/data-structure/container-element/)، [محل‌های قالب](https://developers.elementor.com/docs/themes/).


## نسخه ۳.۷ — شخصی‌سازی قالب و مهارت درصدی

- در قدم «قالب و رنگ»، ۳۲ رنگ آماده و ۱۱ رنگ مستقل با انتخابگر و کد HEX وجود دارد: تیتر، متن، دکمه و متن آن، هیرو، سطح کارت‌ها و نوار مهارت.
- متن تیترها، برچسب‌ها، دکمه‌ها، منو، آمار و پاورقی؛ اندازه متن و تیتر هیرو، گردی گوشه، فاصله بخش‌ها و تعداد ستون پروژه قابل تنظیم‌اند. در همان قدم می‌توان بخش‌ها را پنهان و با فلش‌ها مرتب کرد.
- در قدم «اطلاعات شما»، نمایش مهارت را روی «فهرست عادی» یا «نوار درصدی» بگذارید. مقدار هر مهارت بین ۰ و ۱۰۰ تنظیم می‌شود؛ ورودی مانند `طراحی:۵۰` هم پذیرفته می‌شود. فهرست عادی نوار نمایشی ندارد.
- تنظیمات در پیش‌نویس و پشتیبان JSON، HTML مستقل و ZIP وردپرس نگهداری می‌شوند. ویجت مهارت درصدی در المنتور، Progress بومی نسخه رایگان است و درصد آن داخل المنتور هم قابل تغییر است. داده‌های کلاسیک و اسناد المنتور پس از ساخت مستقل‌اند؛ تغییر Customizer، سند المنتور ویرایش‌شده را بازنویسی نمی‌کند.
- قاب سه‌بعدی تصویر ویزارد با حاشیهٔ سفید و بنفش در هیرو حرکت شناور دارد. شبکهٔ نقطه‌ای بنفش با حرکت نشانگر در همان بخش ظاهر می‌شود، از دور نشانگر کنار می‌رود و به‌نرمی محو می‌شود.
- بررسی: ۲۰ تست خودکار، بررسی نحوی PHP تمام شش قالب، آزمون مرورگر برای رنگ/متن/ترتیب/نوار ۵۰٪ و مشاهده واقعی رد ماوس؛ ذخیره، رندر و ویرایش Progress در هر شش قالب روی WordPress 7.1.4 و Elementor Free 4.3.6 انجام شد. این ویرایش، نصب قالب در محیط آزمایشی را بررسی کرده؛ انتشار روی هاست کاربر انجام نشده است.

### انتشار با لینک ثابت

پس از پیکربندی ورود گیت‌هاب و مخزن خصوصی داده، در مرحلهٔ «دامنه و خروجی» گزینهٔ «انتشار و ساخت لینک» فعال است. آدرس عمومی هر حساب در مسیر `/p/<GitHub user ID>` ثابت می‌ماند. پیش‌نویس و نسخهٔ منتشرشده جدا ذخیره می‌شوند. دکمهٔ «به‌روزرسانی سایت» آخرین پیش‌نویس را روی همان آدرس منتشر می‌کند و «لغو انتشار» آدرس را تا انتشار دوباره غیرفعال می‌کند. برای استفاده از لینک روی اینترنت، برنامه باید روی هاست Node.js یا Docker اجرا شود و `APP_ORIGIN` روی آدرس عمومی برنامه تنظیم باشد.
